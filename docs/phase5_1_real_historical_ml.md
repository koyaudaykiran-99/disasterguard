# AI-DisasterGuard — Phase 5.1: Real Historical Data + ML Retraining Technical Report

## 1. Real Historical Data Pipeline Overview
Phase 5.1 transitions AI-DisasterGuard from a purely synthetic prototype machine learning model into an evidence-based, scientifically honest disaster intelligence system powered by real historical meteorological reanalysis data.
Prior to Phase 5.1, the machine learning models (`flood_classifier_v1.joblib` and `flood_depth_regressor_v1.joblib`) were trained exclusively on synthetic data generated via uniform distributions with heuristic mathematical formulas (`ml/synthetic/generator.py`). While effective for initial system plumbing and user interface testing, synthetic models lack meteorological realism, temporal auto-correlation, and operational validity.

In Phase 5.1, a complete historical data pipeline was engineered from ingestion to inference:
1. **Historical Reanalysis Data**: Ingestion of 26,304 hourly observations (2022–2024) from ECMWF ERA5-Land reanalysis for the Greater Chennai metropolitan area.
2. **Data Hygiene & Validation**: Strict physical bounds checks, missing value resolution, and outlier audits with an automated data quality report.
3. **Temporal Feature Engineering**: 11 physics-aligned features capturing multi-scale rainfall accumulation (1h, 3h, 6h, 12h, 24h) and atmospheric barometric trends.
4. **Chronological Splitting**: Strict 70% Train, 15% Validation, and 15% Test chronological temporal partition guaranteeing zero future leakage.
5. **Rigorous Benchmarking**: Evaluating trivial baselines (Dummy, Linear, Logistic) against advanced ensemble candidates (Random Forest, Gradient Boosting) with an explicit priority on minimizing dangerous false negatives.
6. **Provenance Tracking & Manifest**: Machine-readable metadata (`model_manifest.json` and `registry.json`) detailing data lineage, performance metrics, and runtime policies.
7. **Transparent Command Centre UI & Advisory AI**: UI badges and evaluation modals distinguishing real models from synthetic demos, paired with strictly read-only AI agent tools.
8. **Inviolate Human Barrier**: Unbroken enforcement of the Phase 3.5 Human Operator Confirmation Barrier (`RescueAssignment == 0` without explicit operator dispatch).

## 4. Scientific Honesty & Label Truth Policy
In disaster risk management, intellectual honesty is paramount.
* **No Invented Flooding**: The ECMWF ERA5-Land dataset records atmospheric and surface variables (precipitation, temperature, dew point, pressure, wind). It does **not** contain ground-truth urban inundation depths or municipal drainage telemetry.
* **Label Integrity**: Phase 5.1 explicitly trains models to predict **meteorological rainfall severity** and **quantitative rainfall accumulation (6h forward window)** rather than fabricating ground-truth flood depths.
* **Labeling Policy**: Synthetic models are explicitly labeled `"SYNTHETIC_PROTOTYPE"`. Predictions generated by real models are tagged `"historical_real"` with version `"v2.0-real-data"`.

## 5. Data Cleaning & Ingestion Architecture
Implemented in `ml/ingestion/data_loader.py`:
* **HistoricalDataLoader**: Ingests raw CSV data, parses ISO-8601 timestamps with UTC awareness, normalizes column names (`precipitation` -> `rainfall_1h`, `surface_pressure` -> `pressure_hpa`, `wind_speed_10m` -> `wind_speed_kmh`).
* **DataValidator**:
  * Enforces schema conformance (6 core numerical parameters).
  * Validates physical bounds:
    * `rainfall_1h`: [0.0, 300.0] mm
    * `temperature`: [-10.0, 60.0] °C
    * `humidity`: [0.0, 100.0] %
    * `pressure`: [850.0, 1080.0] hPa
    * `wind_speed`: [0.0, 250.0] km/h
  * Audits 3-sigma statistical outliers and inter-quartile range (IQR) anomalies.
  * Ensures zero forward fill leakage across long gap intervals.

## 7. Feature Engineering Specification (11 Temporal Features)
Implemented in `ml/preprocessing/temporal_features.py`:
1. `rainfall_1h`: Immediate hourly precipitation (mm)
2. `rainfall_3h`: 3-hour rolling cumulative rainfall (mm)
3. `rainfall_6h`: 6-hour rolling cumulative rainfall (mm)
4. `rainfall_12h`: 12-hour rolling cumulative rainfall (mm)
5. `rainfall_24h`: 24-hour rolling antecedent precipitation index (mm)
6. `temperature`: Ambient temperature (°C)
7. `humidity`: Relative humidity (%)
8. `pressure`: Barometric atmospheric pressure (hPa)
9. `wind_speed`: Surface wind velocity (km/h)
10. `pressure_change_3h`: 3-hour barometric delta ($P_t - P_{t-3}$), key indicator of tropical cyclonic depression
11. `humidity_trend_3h`: 3-hour relative humidity delta ($H_t - H_{t-3}$), precursor to moisture saturation

**Targets**:
* `rainfall_category`: IMD-aligned multi-class risk target (`LOW`: <15.6mm, `MODERATE`: 15.6–64.4mm, `HIGH`: 64.5–115.5mm, `EXTREME`: >115.5mm in 24h antecedent + 6h forward).
* `predicted_rainfall_6h_mm`: Continuous 6-hour forward cumulative precipitation.

## 8. Chronological Splitting Strategy & Zero Leakage Proof
Standard random $K$-fold cross-validation or `train_test_split(shuffle=True)` creates massive temporal leakage in meteorological time series because consecutive hours have autocorrelation near $0.95$.
Phase 5.1 implements strict chronological partitioning:
* **Training Set (70%)**: 18,391 observations (`2022-01-02 00:00 UTC` to `2024-02-07 06:00 UTC`)
* **Validation Set (15%)**: 3,941 observations (`2024-02-07 07:00 UTC` to `2024-07-20 11:00 UTC`)
* **Test Set (15%)**: 3,942 observations (`2024-07-20 12:00 UTC` to `2024-12-31 17:00 UTC`)
* **Verification Proof**: $\max(T_{\text{train}}) < \min(T_{\text{val}}) < \max(T_{\text{val}}) < \min(T_{\text{test}})$. Zero future information is accessible to the training pipeline.

## 12. Dangerous-Event Recall & False-Negative Analysis
In life-critical emergency management, **false negatives are catastrophic**, while false positives cause manageable precautionary alerts.
* Standard accuracy is misleading: A dummy model that always predicts `LOW` achieves $87.21\%$ accuracy while missing $100\%$ of dangerous floods!
* In the 3,942 test observations, 48 dangerous events occurred (`HIGH` or `EXTREME` rainfall).
* `BalancedRandomForestClassifier` achieved the highest dangerous-event recall at **18.75%**, detecting almost double the dangerous events of Logistic Regression ($10.42\%$) and infinitely better than the naive baseline ($0\%$).
* Both the classification metrics and comparison logs explicitly record `dangerous_event_recall`, `missed_dangerous: 39`, and `actual_dangerous: 48`.

---

## 13. Model Selection Justification
* **Selected Classifier**: `BalancedRandomForestClassifier` (`rainfall_classifier_v2.joblib`).
  * *Reasoning*: Delivers superior dangerous-event recall ($18.75\%$), high weighted F1 ($0.8798$), and robust non-linear thresholding across multi-scale rainfall windows.
* **Selected Regressor**: `RandomForestRegressor` (`rainfall_regressor_v2.joblib`).
  * *Reasoning*: Achieves the lowest test Mean Absolute Error ($1.59\text{ mm}$), lowest RMSE ($3.99\text{ mm}$), and highest variance explained ($R^2 = 0.4079$).

## 15. Model Mode Policy (REAL_HISTORICAL vs SYNTHETIC)
Governed by environment variable `ML_MODEL_MODE`:
* `REAL_HISTORICAL` (Default): Loads `rainfall_classifier_v2` and `rainfall_regressor_v2` trained on ERA5-Land real data.
